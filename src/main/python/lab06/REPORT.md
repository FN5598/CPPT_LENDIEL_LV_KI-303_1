## Мета

Створити модульний Python-застосунок для читання, перевірки й аналізу аптечного
CSV та запису текстового звіту. Порівняно з Java-роботами, ця лабораторна
демонструє колекції Python, comprehensions, параметри функцій, винятки,
віртуальне середовище, pytest, Ruff і пакетування у wheel.

## Реалізація

Програма розміщена в `src/main/python/lab06/`. Вхідні дані зберігаються
в [data/medicines.csv](data/medicines.csv), приклад результату —
у `reports/summary.txt`, який створюється під час запуску й ігнорується Git.

```text
medicines.csv
  → loader.load_records
  → list[MedicineRecord]
  → analysis.make_summary
  → reporting.format_report
  → reporting.write_report
  → summary.txt
```

`models.py` визначає незмінний `MedicineRecord`. `loader.py` читає UTF-8 через
`csv.DictReader`, перевіряє заголовок і значення та перетворює типи.
`analysis.py` виконує відбір і підрахунки без файлових операцій.
`reporting.py` формує текст і записує його через `Path.open` та `with`.
`errors.py` визначає `DataError`, а `cli.py` поєднує кроки й обробляє аргументи.
`__main__.py` забезпечує запуск через `python -m lab06`.

### Формат CSV

Заголовок і порядок п'яти стовпців перевіряються точно:

```csv
name,form,price,days_left,prescription
```

| Поле | Тип | Перевірка |
| --- | --- | --- |
| `name` | `str` | Непорожня назва після видалення крайніх пробілів |
| `form` | `str` | Непорожня форма; крайні пробіли видаляються, регістр зберігається |
| `price` | `float` | Скінченне невід'ємне число з десятковою крапкою |
| `days_left` | `int` | Невід'ємне ціле число |
| `prescription` | `bool` | `true/yes/1` або `false/no/0`, без урахування регістру |

Приклад екранованого поля:

```csv
"Vitamin C, ""Plus""",Pills,12.50,30,yes
```

Назва після читання — `Vitamin C, "Plus"`. Коми та подвоєні лапки обробляє
стандартний модуль `csv`, а не `split(",")`.
Нульовий файл і файл лише з правильним заголовком дають порожній список.
Неправильний заголовок, відсутні чи зайві значення є помилкою.

### Колекції та функції

Завантажені й відібрані записи зберігаються в списках, кількість за формою —
у словнику, унікальні форми — у множині. Відбір і побудова агрегатів виконуються
через list, dict і set comprehensions.

`make_summary(records, *metrics, max_days_left=30, **labels)` демонструє типове
значення, додаткові позиційні аргументи як кортеж та іменовані аргументи як
словник. Приклад:

```python
summary = make_summary(
    records,
    "price",
    "days_left",
    max_days_left=30,
    price="Total price",
    days_left="Total days remaining",
)
```

Відбір застосовує `days_left <= 30`. Для відібраних записів обчислюються
кількості за формою, множина форм, середня ціна й суми метрик. Найближчий термін
визначається за `(days_left, name.casefold())`; за повністю рівного ключа
залишається перший вхідний запис. Форми й мітки метрик сортуються перед
форматуванням. За порожнього відбору кількість нульова, середня ціна й
найближчий термін — `None`; суми заданих метрик нульові.

### Обробка помилок

`DataError` повідомляє про хибні значення й файлові операції. Для помилок
запису CSV номер береться з `reader.line_num`, тому порожні й багаторядкові
поля не зміщують номери наступних записів. Для самого багаторядкового запису
це номер останнього фізичного рядка. `raise ... from error` зберігає
першопричину числових, файлових, CSV- та UTF-8-помилок.

CLI повертає `0` після успішного запису та `2` для очікуваної помилки;
повідомлення про помилку надходить у `stderr`. Хибні аргументи також дають
`2` через `argparse`. `--help` і `--version` завершуються кодом `0` без
вхідного й вихідного шляхів. Версія береться з метаданих установленого пакета
або з `pyproject.toml` під час запуску без установлення. Запис звіту виконується в UTF-8 через `with`, що
гарантує закриття файла, але не атомарність запису.

командах мають різні шляхи.

## Збірка і запуск

Команди виконуються з каталогу `src/main/python/lab06/`.

macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
python -m pytest
ruff check .
ruff format --check .
python -m build
python -m lab06 --input data/medicines.csv --output reports/summary.txt
python -m lab06 --help
python -m lab06 --version
```

Windows PowerShell після `python -m venv .venv`:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
python -m pytest
ruff check .
ruff format --check .
python -m build
python -m lab06 --input data/medicines.csv --output reports/summary.txt
```

Вхідний і вихідний шляхи задаються парою `--input` і `--output`. Попередній
позиційний виклик `python -m lab06 data/medicines.csv reports/summary.txt`
також підтримується; змішувати два способи не можна.
Параметр `--max-days-left` змінює поріг відбору:

```bash
python -m lab06 --input data/medicines.csv --output reports/custom.txt --max-days-left 10
```

Wheel створюється в `dist/`. Перевірка конкретного пакета без dev-залежностей:

```bash
python -m venv .venv-wheel
.venv-wheel/bin/python -m pip install --no-deps dist/kzp_lab06_v11-6.0.0-py3-none-any.whl
.venv-wheel/bin/python -m lab06 --input data/medicines.csv --output reports/wheel-summary.txt
```

У Windows замість `.venv-wheel/bin/python` використовується
`.\.venv-wheel\Scripts\python.exe`. Runtime-залежностей пакет не має.
`.venv/`, `.venv-wheel/`, `build/`, `dist/` і кеші ігноруються Git.

## Відповіді на контрольні питання

### 1. Яку роль виконує pyproject.toml?

Він описує пакет і правила роботи інструментів: назву, версію, потрібний Python,
залежності, спосіб побудови, налаштування pytest і Ruff. Це дозволяє відтворити
проєкт замість ручного встановлення невідомого набору бібліотек.

### 2. Навіщо створюється віртуальне середовище?

Воно відокремлює бібліотеки одного проєкту від інших. Версія pytest для цієї
роботи не повинна змінювати інше середовище. Каталог venv не передається через
Git — передаються правила його створення та встановлення залежностей.

### 3. Чому CSV відкривається з newline=""?

Щоб модуль `csv` сам обробляв межі рядків, зокрема перенесення всередині
екранованого поля. Текстовий режим файла не повинен передчасно змінювати їх.

### 4. Які типи повертає DictReader без перетворення?

Для звичайного коректного запису — словник із рядковими ключами й значеннями.
Текст `"12.50"` ще не є числом. За хибної ширини можуть з'явитися `None`
для відсутнього значення або список зайвих значень під ключем `None`, тому
ширину перевіряємо окремо.

### 5. Чому split(",") не є CSV-парсером?

Він розділить кому всередині назви так само, як межу стовпців. Він не розуміє
екранованих лапок і багаторядкових полів. Модуль `csv` знає ці правила й
залишає екрановану назву одним значенням.

### 6. Як відрізняються список, словник і множина?

Список зберігає порядок і повтори записів. Словник дає значення за ключем,
наприклад кількість для `Pills`. Множина залишає кожну форму лише один раз;
для передбачуваного виводу її потрібно відсортувати.

### 7. Коли comprehension кращий, а коли потрібний цикл?

Короткий comprehension одразу показує результат і просту умову відбору.
Якщо потрібні послідовні перевірки кількох полів, точні помилки або файлові
операції, звичайний цикл простіше читати й пояснювати.

### 8. Що містять *args і **kwargs?

Перша конструкція збирає додаткові позиційні аргументи в кортеж, друга —
іменовані аргументи в словник. У `make_summary` це метрики та їхні підписи:
`metrics` і `labels` працюють за тим самим правилом.

### 9. Чому змінний типовий аргумент небезпечний?

Об'єкт створюється під час визначення функції й повторно використовується
в наступних викликах. Додані до типового списку елементи залишаться для
наступного виклику. Краще використати `None` і створити список усередині;
незмінне типове число `30` цієї проблеми не має.

### 10. Як raise ... from error зберігає першопричину?

Воно пов'язує доменний виняток із початковим через `__cause__`. Користувач
отримує повідомлення про поле й рядок, а під час діагностики можна побачити
конкретний початковий `ValueError`, `OSError` чи інший виняток.

### 11. Навіщо розділяти завантаження, аналіз і запис?

Кожен модуль відповідає за один крок. Зміна місця збереження не повинна
змінювати формулу середньої ціни. Обчислення можна перевіряти на списку
без створення CSV для кожного тесту.

### 12. Яку гарантію дає with?

При виході з блоку контекстний менеджер завершує роботу з файлом, навіть
якщо виник виняток. Це гарантує закриття ресурсу, але не успішний або
атомарний запис усіх даних.

### 13. Чому потрібний детермінований порядок звіту?

Однакові результати повинні мати однакове розташування рядків, щоб звіти
можна було порівнювати й тестувати. Тому форми й мітки сортуються, числовий
формат задається явно. Рівні ключі пошуку найближчого терміну обробляються
за правилом, описаним у розділі «Реалізація».

### 14. Що перевіряти для порожнього CSV?

Окремо нульовий файл і правильний заголовок без записів: обидва дають `[]`.
Ще потрібний порожній відбір із непорожнього CSV: кількість нульова,
найближчого терміну й середньої немає, суми активних метрик нульові.
Хибний заголовок не стає правильним через відсутність записів.

### 15. Чим тест поведінки відрізняється від тесту реалізації?

Він перевіряє результат, виняток, код CLI або створений файл. Такий тест
продовжує працювати після заміни циклу на comprehension. Вимога конкретної
внутрішньої змінної може зламати тест, навіть коли результат правильний.

### 16. Які файли знаходить pytest?

За типовими правилами — `test_*.py` і `*_test.py`, а в них функції `test_*`
та відповідні тестові класи. У проєкті пошук обмежено каталогом `tests`
через `testpaths` у конфігурації.

### 17. Які перевірки виконує Ruff?

`ruff check` застосовує ввімкнені правила: знаходить, наприклад, невикористані
імпорти, невідомі імена й типові помилки. `ruff format --check` окремо перевіряє
оформлення. Ruff не замінює тести обчислень чи повноцінний аналіз типів.

### 18. Які коди завершення CLI?

`0` означає успішний запис, `2` — очікувану помилку даних чи файлової операції.
Хибні аргументи також дають `2` через `argparse`. Помилки даних виводяться
в `stderr`, повідомлення про успіх — у `stdout`.

### 19. Навіщо автоматично запускати тести, аналізатор і пакетування?

Вони перевіряють різні речі. Тести перевіряють поведінку, Ruff — правила
й оформлення, build — можливість створити встановлюваний пакет. Успішний
wheel не доводить правильності аналізу CSV, а правильні тести не доводять,
що всі потрібні файли включено до пакета.

### 20. Що потрібно задекларувати у звіті?

Варіант і середовище, формат CSV, правило порожнього входу, структуру коду,
алгоритм, помилки, повний приклад звіту, команди й фактичні результати
перевірок. Також потрібний чесний опис використання ШІ та власної роботи;
заплановану перевірку не слід називати виконаною.
