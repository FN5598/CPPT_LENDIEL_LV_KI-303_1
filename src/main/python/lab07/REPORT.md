# Звіт до лабораторної роботи № 7

## Тема

Об'єктно-орієнтована обробка даних у Python.
Варіант 11 — аптека: `Medicine`, `PrescriptionMedicine`, `FreeMedicine`;
спільна операція `availability_score()`, підсумок для препаратів із близьким терміном.
Локальні перевірки: macOS, Python 3.11.9. Версія пакета — 7.0.0.

## Мета

Перенести перевірки та поведінку в сутності, використати властивості,
наслідування, протокол, спеціальні методи й незмінний підсумок.
Зберегти CSV і зовнішні результати попередньої роботи.

## Стан до і після

Методичні вказівки описують перехід від словників. Фактична робота № 6
вже мала `MedicineRecord` як frozen dataclass; її підсумок був словником,
а перевірки та обчислення — зовнішніми функціями. Цей факт збережено у звіті.

| Аспект | Робота № 6 | Робота № 7 |
| --- | --- | --- |
| Запис | Незмінний MedicineRecord | Medicine з двома підтипами |
| Перевірки | Loader | Конструктор і setter; loader перетворює типи |
| Відмінна поведінка | Поле prescription | Поліморфний availability_score() |
| Підсумок | TypedDict із колекціями | Frozen ReportSummary зі snapshots |
| Аналіз | Функції над записами | Функції над AvailableMedicine |
| CSV і звіт | Контрольний формат | Повністю збережено |

## Реалізація

### Модель і властивості

Абстрактний `Medicine` ініціалізує назву, форму, ціну й термін.
Назва та форма нормалізуються через strip і доступні лише для читання.
`price` має getter/setter: приймає число ≥ 0, відхиляє bool, NaN, infinity
і рядки. `days_left` приймає лише int ≥ 0, зокрема 0, 30 і 31;
bool не вважається кількістю днів. Setter спочатку перевіряє значення,
потім змінює внутрішнє поле, тому невдале присвоєння не псує стан.

`__str__` дає короткий опис, `__repr__` — назву підтипу й усі поля.
`__eq__` порівнює однакові конкретні підтипи за всіма спільними полями;
для несумісного об'єкта повертає NotImplemented. Сутності змінювані,
тому їх не можна хешувати. Найближчий термін обирається через key
`(days_left, name.casefold())`; за повного збігу лишається перший запис.

### Dataclass

`ReportSummary` має `frozen=True`, `slots=True`: source_count, selected,
form_counts, forms, nearest_expiry, average_price, metrics, availability_scores.
`count` обчислюється з selected. Selected і nearest_expiry містять незмінні
`MedicineSnapshot`, решта колекцій — tuple або frozenset.
Так незмінність поширюється й на вкладені результати: зміна вихідної
сутності після аналізу не змінює вже обчислений звіт.

### Підтипи та протокол

Підтипи викликають `super().__init__`, повторно використовуючи перевірки.
Рецептурний статус доступний лише для читання й визначається підтипом.
PDF задає назву операції, але не числову формулу, тому прийнято навчальні формули:

- FreeMedicine: `days_left / (days_left + 30)`.
- PrescriptionMedicine: `0.5 * days_left / (days_left + 30)`.

При терміні 30 днів результати 0.5 і 0.25; при 0 днів обидва дорівнюють 0.
Це навчальний індекс доступності, а не медична рекомендація.
`AvailableMedicine` описує властивості name, form, price, days_left і метод.
`best_available` викликає метод через протокол; `make_summary` також
обчислює оцінки поліморфно. Analysis не перевіряє конкретні підтипи.
Тест стороннього класу без наслідування доводить duck typing.
Оцінки залишаються внутрішнім результатом, щоб не змінювати попередній звіт.

### Структура модулів і обробка помилок

`models` зберігає стан і контракт; `loader` читає CSV та обирає підтип
лише на межі завантаження за prescription; `analysis` відбирає й агрегує;
`reporting` форматує та записує; `errors` визначає DataError;
`cli` перевіряє аргументи й координує виконання.

Заголовок `name,form,price,days_left,prescription` не змінено.
CSV читається через DictReader(strict=True), with, Path, UTF-8.
Хибні поля мають контекст фізичного рядка reader.line_num.
Причину перетворення або помилки моделі збережено через raise from.
Помилки читання, кодування, CSV і запису перетворюються на DataError.
CLI повертає 2 при помилці й 0 при успіху; імпорт не запускає програму.

## Результати роботи та порівняння звітів

Контрольний CSV роботи № 6 збережено без змін. Обидві реалізації дають:

```text
Pharmacy Register Report
CSV records: 10
Selection threshold: up to 30 days remaining, inclusive
Selected records: 9
Medicine count by form:
  Liquid: 6
  Pills: 3
Unique forms: Liquid, Pills
Nearest expiry: Pakistani (Pills), 1 day remaining
Average price of selected medicines: 4.24
Total days remaining: 82.00
Total price: 38.20
```

Попередній словниковий підсумок і новий об'єктний підсумок формують
однаковий повний текст. Регресійний тест порівнює тексти для трьох входів
(medicines, boundaries, empty) і п'яти меж (-1, 0, 1, 30, 31): 15 комбінацій.
Контрольний текст також зберігається у `data/expected-report.txt`.
Запис створює батьківські папки, використовує with, UTF-8 і LF.
Форми й метрики впорядковані; порожній вхід дає явні no records/no data.

## Збірка і запуск

Команди й встановлення wheel наведено у [README.md](README.md).
CLI підтримує --help, --version, --input, --output і --max-days-left;
довідка й версія не потребують шляхів. Два позиційні шляхи також підтримуються.

```bash
python -m pip install -e ".[dev]"
python -m lab07 --help
python -m lab07 --version
python -m lab07 --input data/medicines.csv --output reports/summary.txt
python -m pytest
ruff check .
ruff format --check .
python -m build --wheel
```

## Тестування та пакетування

85 pytest-тестів перевіряють властивості, відмову без зміни стану,
рівність, str/repr, frozen dataclass, підтипи, duck typing, дублікати,
граничні терміни, порожній вхід, пошкоджені поля, quoting, UTF-8,
номер рядка, файлові помилки та CLI. Тести роботи № 6 також збережено.
Wheel `kzp_lab07_v11-7.0.0-py3-none-any.whl` містить код і дані;
встановлення й запуск перевірено в окремому venv.
Локальні результати не означають підтвердження виконання на інших ОС.

## Академічна доброчесність

Під час виконання лабораторної роботи використано невелику допомогу ШІ
для документування функцій. Також використано чатбот для отримання
додаткової інформації з теми лабораторної роботи № 7.

## Відповіді на контрольні питання

1. Клас описує стан і поведінку; екземпляр має конкретні значення цього стану.
2. __init__ задає початковий стан; self посилається на поточний екземпляр.
3. Property дозволяє перевіряти доступ як до звичайного поля.
4. Setter записує у _поле, щоб не викликати себе нескінченно.
5. Dataclass генерує конструктор, repr і порівняння за полями.
6. Frozen забороняє присвоєння полям; вкладені колекції теж мають бути незмінними.
7. Str читає користувач; repr допомагає діагностувати стан об'єкта.
8. Eq повертає NotImplemented, дозволяючи Python спробувати іншу сторону.
9. Key зручний, коли порядок залежить від задачі, а не від природи сутності.
10. Super звертається до наступної реалізації за MRO та повторно використовує її.
11. MRO — порядок пошуку методів; він визначає, яка реалізація виконається.
12. Duck typing означає, що об'єкт підтримує потрібні операції без вимоги наслідування.
13. Protocol формально описує структурний контракт для перевірки типів і читача.
14. Умови за підтипами змушували б змінювати analysis при кожному розширенні.
15. CSV-словник перетворюється на сутність у loader, до аналізу.
16. Імпорт має надавати API, без читання аргументів і створення файлів.
17. Тестуються зовнішні правила: setter, рівність, незмінність і поліморфна поведінка.
18. Pytest перевіряє поведінку, Ruff — стиль і помилки, wheel — встановлюваний пакет.
19. Потрібні порожній вхід, дубль, межа, хибний тип, NaN, quoting й файлові помилки.
20. Звіт має містити модель, результати, сумісність, перевірки, середовище і внесок ШІ.

## Висновки

Робота № 7 перенесла інваріанти в модель і додала різну поведінку підтипів
без розгалужень у analysis. Незмінний підсумок відділяє обчислений результат
від змінюваного стану. Protocol, loader і поведінкові тести створюють основу
для подальшого розширення зберігання й Python-ідіом.
